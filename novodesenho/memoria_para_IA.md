## Armadilhas e técnicas (não redescobrir)

- **Disco e LFS:** projetos reais em `ttwa_files/` (LFS) mudam ao abrir e o Git reprocessa (já encheu 33 GB em `.git/lfs/tmp`); marcados `skip-worktree` só na máquina de desenvolvimento (`git update-index --no-skip-worktree <arquivo>` desfaz); nunca `git add -A`.
- **Intel:** `numpy<2` obrigatório; pacote Intel roda sob Rosetta no M4 (`arch -x86_64 TTWtools --selftest`; servidor com `--mode web --port <livre>`): serve para reproduzir problemas do pacote x86_64, **não** a lentidão da CPU real. Porta 8791 pode estar ocupada por **outra** sessão do Claude; usar porta livre (`socket` com porta 0) e só encerrar processo alheio se o usuário pedir.
- **WebKit/WKWebView:** requisição sem resposta por ~60 s cai como "sem conexão"; `<progress>` nativo estilizado vira barra cheia e parada no macOS 12.
- **WebKit antigo (Safari 17.6, macOS 12 Intel), 2026-10-04:** `color-mix()` fora de `srgb` é defeituoso — com `transparent` o resultado sai **opaco** (botão inativo preto, item do menu ativo laranja chapado, mouse-over preto) e entre duas opacas erra o matiz (ex.: azul vira rosa). Tailwind 4 e daisyUI 5 emitem `color-mix(in oklab/oklch, ...)` e testam `in lab` no `@supports`; o plugin `ttw-safari-color-mix` (`frontend-vue/vite.config.js`, fase `generateBundle`) troca toda interpolação para `srgb` no CSS final — para cor+transparente é idêntico, e é o que faz o WebKit antigo pintar certo. O plugin cobre todo o CSS do build; em estilo inline no JS (ex.: `SpotlightCard.vue`), escrever `srgb` direto. **Justificação no Leitor:** o CSS permite não justificar espaço não colapsável, e o WebKit teve um bug nisso (bugs 84448/245947; corrigido por volta do Safari 16). `.reader-text.is-justified` passou a usar `pre-line` (colapsa espaços e preserva quebras) em vez de `pre-wrap`, garantindo a justificação. **A confirmar no Intel** se era essa a causa do botão "não funcionar"; o WebKit novo do Playwright justifica os dois, mas `pre-line` é o modo seguro.
- **Lookbehind em regex quebra no WebKit do macOS 12 (2026-10-05):** o `markdown.js` dividia as células de tabela com `split(/(?<!\\)\|/)`; esse WebKit (Safari 17.6 no macOS 12.7.6) recusa a expressão (`SyntaxError: Invalid regular expression: invalid group specifier name`), o render do tópico lança, o Vue aborta a tela e **só o tópico com tabela fica em branco** (a KFA no Tauri; no Chrome/V8 funciona). Corrigido trocando o lookbehind por um marcador: `replace(/\\\|/g, '\u0000').split('|')...`. Regra: **não usar lookbehind `(?<=`/`(?<!`** no frontend; o e2e do Playwright (WebKit novo) não pega. O app instalado precisa de novo build do frontend para valer.
- **Tabela com 1ª coluna fixa e hover (2026-10-04, Passo 5 de `leitor_kfa.md`):** em `.ttw-scroll .table`, a regra da 1ª célula sticky tem `background: var(--color-base-100)` com especificidade (0,2,0) e vence `.table :where(tbody tr:hover)` (0,1,0) mesmo vindo depois no arquivo — a linha destacava, mas a 1ª coluna não. A célula sticky precisa de fundo **opaco** (conteúdo rola por baixo), então não dá para usar `color-mix(..., transparent)` no lugar do `base-100`/zebra: a saída foi regras extras escopadas a `.ttw-scroll` com o mesmo mix da linha, porém composto sobre `--color-base-100` (opaco). No e2e, checar o fundo com `getComputedStyle` do `<tr>` (as demais células são transparentes e não refletem o realce da linha). O `background: var(--color-primary)` que aparece antes do `color-mix` no CSS do build é o fallback do lightningcss para `target: safari16` (o `@supports color-mix` cobre o Safari 17.6).
- **SQLite:** `_connect` recria os índices do esquema a cada abertura (benchmarks que medem conjuntos de índices devem montar a conexão à mão); criar tabela com `CREATE TABLE AS` perde a PK e `WITHOUT ROWID` (consultas lentas); `ATTACH` na conexão aberta com `uri=True`; limite padrão de 10 bancos anexados; `DELETE FROM tokens` com a view ativa falha: qualificar `main.tokens`; `VACUUM` pede até 2× o espaço; `PRAGMA wal_checkpoint(TRUNCATE)` antes de medir tamanho.
- **Shell no macOS:** `sed -i ''` (com aspas vazias); `cmd1 && cmd2` com `cmd1` falho pula tudo (conda não ativa); `git add` com caminho de arquivo já removido aborta o comando inteiro; `pgrep -f nome` casa com o próprio comando de espera (usar `[n]ome`); `sleep` longo em primeiro plano é bloqueado (usar laço `until` em segundo plano); comandos `rm -rf $VAR/...` são bloqueados (usar caminho literal).
- **Áudio do usuário (.opus):** `ffmpeg -ar 16000 -ac 1 audio.wav` e `faster-whisper` (modelo `small`, `language="pt"`) num venv isolado; o `av` novo quebra `decode_audio` (`metadata_errors`): passar o áudio como array numpy lido com o módulo `wave`.
